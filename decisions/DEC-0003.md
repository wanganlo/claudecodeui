## Decision

将本次分支新增的 redesign 聊天组件（`CodeBlock`、`ChatInterface`、`ChatComposer`、`MessageComponent`、`ImageAttachment`、`useChatComposerState`、`classifyFile` 等）合并到原 claude-ui 前端统一构建中；不再单独部署 `/claude/ui/` 子路径，也不再运行独立的 redesign 后端（`server/index.mjs`）。

## Options Considered

| Option | Pros | Cons |
|--------|------|------|
| A. 保持 redesign 独立子路径 `/claude/ui/` + `server/index.mjs` | 两套界面互不干扰，可渐进迁移 | 维护两套后端/前端构建，nginx 配置复杂，旧 API 与新界面跨服务调用 |
| B. 合并进原前端，统一走 `/claude/` 和 cloudcli (3001) | 单一构建、单一后端、nginx 简洁；新组件已在 `MainContent.tsx` 中使用 | 需要清理 redesign 服务和静态文件，确认新组件依赖的 API 原后端都已具备 |

## Rationale

- 新聊天组件本身已经通过 `src/components/main-content/view/MainContent.tsx` 接入原前端，技术上没有必须独立部署的理由。
- 原后端 `server/index.js` 已提供新组件所需的 `/api/providers/sessions`、`/api/commands/execute`、`/api/projects/*/upload-images` 等接口，`server/index.mjs` 的接口并不被新组件使用。
- 用户明确要求「合并进原有前端」，优先遵循业务方决策，避免生产环境存在两套并行入口。

## Expected Outcome

- `https://hermes.cy-pharm.com:9080/claude/` 继续由 cloudcli (3001) 提供统一服务。
- 新 chat 组件随原前端构建一起发布，无需单独构建 `/var/www/claude/ui/`。
- nginx 不再包含 `/claude/ui/` 和 `/claude/api/` 路由。
- `claude-ui-redesign.service` 停止并禁用，释放 9181 端口。

## Context

- 相关文件：`/etc/nginx/conf.d/hermes-proxy.conf`、`server/index.mjs`（保留源码，不再运行）、`dist/`、`dist-server/`。
