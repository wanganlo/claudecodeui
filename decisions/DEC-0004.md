## Decision

claude-ui 服务端解析 Claude Code 可执行文件时(server/claude-sdk.js):

1. 显式 `CLAUDE_CLI_PATH`、探测到的宿主二进制,一律先 `spawn --version` 预检(按路径缓存),通过才传给 SDK 的 `pathToClaudeCodeExecutable`;
2. 预检失败或路径不存在 → `console.warn` 明确告警,**自动回落到 SDK bundled CLI**,不再让坏路径打死所有新会话;
3. 运营规则:**不在 systemd unit 里钉 `CLAUDE_CLI_PATH`**(0922 事故教训),靠 bundled CLI 兜底;要钉必须先在服务同等环境下预检通过。

## Options Considered

| Option | Pros | Cons |
|--------|------|------|
| A. 钉 CLAUDE_CLI_PATH 到宿主 claude(如 nvm 路径) | 用宿主版本,可控 | systemd 干净环境下可能起不来(0922 "exists but failed to launch" 事故);nvm 升级要同步改;重启洗掉 shell 环境即暴露 |
| B. 裸 'claude' 字符串(原实现) | 简单 | SDK 0.3.165 对路径做 existsSync,裸字符串直接抛 "native binary not found"(0922 第一起事故) |
| C. 预检 + 降级兜底(选定) | 钉错/环境坏只降级不打死会话;无钉时 bundled CLI 永可用;告警日志可定位 | 首次会话多一次 --version 预检(缓存后忽略) |

## Rationale

- 0922 一天两起事故:第一起是裸 'claude' 字符串被 SDK existsSync 拒绝;第二起是 CC 按建议钉了 nvm 路径,服务环境起不来。两起都靠"留空 → SDK bundled CLI"这层兜住。
- bundled CLI 与 SDK 版本天然一致,是最稳的默认;宿主二进制只是可选增强,必须证明能启动才采用。
- 降级而非 fail-fast:这是面向磊哥日常使用的内部工具,可用性优先于配置严格性,坏配置用 warn 日志暴露。

## Expected Outcome

- systemd 重启、宿主环境变化、误钉路径,最多产生 warn 日志,不再导致新会话报错。
- 验收规矩保持:修复后必须真发一条消息(WS chat.send 收到 assistant 帧)才算数,0 帧不许解释成"首启偏慢"。
