## Decision

禁止对 claude-ui 直接执行 `git pull` 或 `cloudcli update` 升级到上游 `siteboon/claudecodeui v1.36.1`。若需升级，必须走手工 merge，并在合并后回归以下本地功能：

1. **4 fixes — 通用文件附件**（非图片文件上传、显示、下载）。
2. **B2 多用户隔离 / 超管视图**（`assertOwnsSession`、`requireAdmin`、`userId`/`scopeAll` 透传）。
3. **Claude 动态模型发现 + 3 天缓存**（`UNCACHED_PROVIDERS` 不含 `claude`）。
4. **会话归档按钮 / admin scope 修复**。

## Options Considered

| Option | Pros | Cons |
|--------|------|------|
| A. 直接 `git merge v1.36.1` / `cloudcli update` | 最快拿到上游 bugfix 和新 UI | 会产生 10 个文件冲突；通用附件、B2 鉴权、Claude 模型缓存会被覆盖或删除 |
| B. 手工合并，按文件审查保留本地功能 | 保留所有本地定制；可控升级 | 需要 1-2 小时逐文件解决 + 回归测试 |
| C. 暂不升级，继续基于当前 main 开发 | 零风险 | 错过上游的 attachment 架构改进、lightbox、cross-spawn 统一等 |

## Rationale

- `git merge-tree` 与临时合并分支验证：v1.36.1 相对我们当前 HEAD 产生 **10 个冲突文件**，其中 8 个 content conflict、2 个 modify/delete conflict。
- 冲突最密集的三块正好是我们最近的核心投入：
  - 附件系统：上游从「通用上传」改为「仅图片 assets + image-attachments」，直接合并会让非图片附件失效。
  - 模型发现：`provider-models.service.ts` 中上游把 `claude` 重新加入 `UNCACHED_PROVIDERS`，会撤销 3 天缓存优化。
  - B2 鉴权：`server/index.js`、`provider.routes.ts`、`user.js` 等多处参数透传会冲突。
- Gemini 支持被上游整体删除，若仍需要该 provider，需在合并时显式保留或迁移。

## Expected Outcome

- 若执行升级，合并后的代码必须同时通过：
  - 非图片附件上传/显示/下载 e2e
  - 普通用户 / 管理员 / 超管视图下的项目、会话、文件访问权限
  - 模型选择器显示实际可用 LLM（含缓存命中）
  - 会话归档/恢复按钮正常
- 避免因自动化升级导致生产环境功能回退。
